# myapp · 我的生活工作台

一个**只给自己用**的工作生活专属 App。纯前端、零依赖、不需要登录和联网，直接用浏览器打开就能用；所有数据保存在本机浏览器里，刷新、关闭、重启电脑都不会丢。

## 1. 项目解决什么问题

日常的工作和生活分散在备忘录、日历、Excel、各种 App 里：今天要做什么、哪条视频数据涨了、哪个客户该跟进了、这周练了几次、今天吃了多少热量——每次都要在几个工具之间来回切。

myapp 把这些收拢到**一个本地页面**里，打开首页就能看到今天该干什么、各模块的关键数字；点进对应模块就能直接维护。它刻意不做账号体系、不做云同步、不做部署，换来的是：**打开快、数据在手、没有隐私顾虑**。

适合的使用场景：

- 每天早上打开首页，看今日计划与快速备忘，顺手加两件事；
- 拍完视频更新内容管线，发布后登记播放/点赞数据，看趋势图；
- 开发任务按看板推进，逾期项在首页就能看见；
- 咨询客户按阶段跟进，记录每次咨询时长与费用；
- 健身、饮食用日历回看每天练了什么、吃了多少；
- 每周导出一次 JSON 备份，换电脑时导入即可。

## 2. 主要功能

| 模块 | 能做的事 |
| --- | --- |
| **首页总览** | 问候语与今日完成率；今日待办清单（可直接勾选、快速加事项）；快速备忘（置顶/删除）；六个模块摘要卡（自媒体本周发布、开发进行中、咨询活跃客户、健身本周训练、饮食热量、游戏本周时长），点卡片直达模块 |
| **今日计划** | 按日期切换（前一天/后一天/回到今天/日历选日期）；新增、编辑、删除事项，可设模块来源、时间、优先级；勾选完成，实时完成率；当日复盘文字（自动保存）；把已完成项一键清理 |
| **自媒体** | 内容管线看板（想法 → 脚本 → 拍摄 → 剪辑 → 已发布，可左右移动阶段）；账号管理（平台 + 昵称）；发布后登记数据（播放、点赞、评论、分享、收藏、涨粉）；**三张统计图表**：单条播放走势折线图、平台播放占比环形图、单条播放 Top5 条形图；发布记录表，逐条计算互动率 |
| **开发工作** | 四列看板（待办 / 进行中 / 评审 / 完成），卡片可左右移动状态；新增工作项（类型、项目、优先级、截止日期、预估工时、描述）；逾期自动标红并在首页汇总；项目管理（新建/改名/改色/删除，删除项目不删工作项）；一键把工作项加入今日计划；按项目与类型筛选 |
| **咨询工作** | 客户按六个阶段管理（线索 / 沟通中 / 已签约 / 交付中 / 已结案 / 已流失）；新增、编辑、**删除客户（二次确认，级联删除其咨询记录）**；登记咨询记录（日期、时长、费用、主题）；本月收入、累计收入、活跃客户、本月时长等指标 |
| **健身计划** | **月历视图**：每天格子里显示练了哪些部位与总组数；点某一天新增训练动作（部位、动作名、组数、次数、重量）；右侧显示当日训练明细、本周训练天数与连续打卡、部位组数分布 |
| **饮食计划** | **月历视图**：每天格子里显示摄入热量与目标完成度；按早/午/晚/加餐记录食物（热量、蛋白、碳水、脂肪）；右侧进度环显示热量完成度、三大营养素条、饮水记录（每次 +250 ml）、当日餐次列表；每日目标可在设置里改 |
| **游戏娱乐** | 游戏库（想玩 / 在玩 / 已通关 / 搁置，评分、平台、已玩时长）；记录本次游玩分钟数，自动累加到总时长；本周游玩时长、在玩数量等统计 |
| **数据与设置** | 手动保存（按钮或 Ctrl+S）与保存时间显示；导出 JSON 备份（文件名带时间戳）；导入备份（先校验格式，非法文件不会破坏现有数据）；各模块数据条数一览；昵称、主题（浅色/深色）、每周起始日、每日饮食目标；一键载入示例数据；危险区清空全部数据（需输入「清空」二字） |

## 3. 安装方法

**不需要安装任何前端依赖，也不需要构建。**

### 方式一：直接打开（最省事）

```bash
git clone <本仓库地址> myapp
cd myapp
# 双击 index.html，或在文件管理器里用 Chrome / Edge 打开
```

### 方式二：本地静态服务器（推荐）

需要一个 Node.js（>= 18）环境，仅用于起一个静态服务，不装任何 npm 包：

```bash
cd myapp
node server.js          # 默认 http://localhost:5173
node server.js 8080     # 指定端口
```

浏览器访问 `http://localhost:5173` 即可。

> 用 `file://` 直接打开也能正常使用；起本地服务是为了让地址稳定、刷新行为与常规网页一致。

### 可选：跑浏览器验收测试

界面测试依赖 Playwright 与 Chromium（仅测试需要，应用本身不需要）：

```bash
npm i -D playwright
npx playwright install chromium
```

## 4. 使用方法

1. **打开应用**：`node server.js` 后访问 `http://localhost:5173`，或直接打开 `index.html`。
2. **左侧导航**在九个模块间切换，地址栏会跟着变成 `#/plan`、`#/dev` 这样的锚点，刷新后停留在当前页。
3. **首页快速添加**：在「今日计划」卡片底部输入框写一件事，按回车即进入今天的清单；「快速备忘」用来丢临时想法。
4. **保存**：每次修改都会自动写入本机浏览器；顶部「保存」按钮或 `Ctrl+S`（macOS 为 `⌘+S`）可手动保存，并在右上角显示「已保存 HH:MM:SS」。
5. **换主题**：右上角「深色 / 浅色」按钮，或在设置页切换，选择会被记住。
6. **备份**：`数据与设置 → 导出备份` 下载 `myapp-backup-YYYYMMDD-HHMM.json`；恢复时点「导入备份」选择该文件（会二次确认，覆盖当前数据）。
7. **先看效果**：`数据与设置 → 载入示例数据`，会填入一份完整演示数据（注意：会覆盖当前内容）。
8. **清空**：`数据与设置 → 清空全部数据`，需要输入「清空」二字才会执行。

### 数据存在哪里

- 位置：当前浏览器的 `localStorage`，键名 `myapp.data.v1`。
- 特点：**同一台电脑 + 同一个浏览器 + 同一个访问地址**才共享数据。换浏览器、换端口、用无痕窗口都看不到原来的数据。
- 因此建议：固定用同一个浏览器和同一个地址（如都走 `http://localhost:5173`），并定期导出 JSON 备份。
- 如果浏览器禁用了本地存储，右上角会显示「本地存储不可用」并弹出提示，不会静默丢数据。

输入：在「今日计划」输入框填 `写完周报`，回车。

界面输出：清单出现 `写完周报`，顶部完成率由 `0%` 变为 `0% 完成`（0/1），左侧导航「今日计划」出现未完成数量角标 `1`。

      "review": "",
      "items": [
        {
          "id": "plan-mwbrk2x1-8f3a",
          "title": "写完周报",

### 示例二：登记一条发布数据 → 出图

输入：`自媒体 → 发布数据 → 登记发布数据`，填标题 `第一条视频`、平台 `抖音`、发布日期选今天、播放 `1200`、点赞 `100`、评论 `10`、分享 `5`、收藏 `20`、涨粉 `30`。

界面输出：

- KPI 区播放量 `1,200`、互动率 `11.3%`（(100+10+5+20)/1200）；
- 「单条播放走势」折线图出现一个数据点（落在近 30 天窗口内才会入图）；
- 「平台播放占比」环形图出现「抖音」分段；
- 「单条播放 Top 5」出现该条目的条形；
- 「发布记录」表格新增一行，末列为单条互动率。

## 6. 测试

```bash
npm test          # 逻辑层 + 数据层，45 项，零依赖
npm run test:e2e  # 浏览器端验收，17 项（需要 Playwright + Chromium）
npm run test:all  # 全部 62 项
```

覆盖范围：

- `tests/core.test.js`：日期/周计算、完成率、自媒体统计与图表数据、开发统计、咨询统计、健身统计、饮食与饮水、游戏时长、导入校验、数据规范化；
- `tests/store.test.js`：localStorage 读写、保存失败处理、订阅通知、导出/导入/清空、刷新后恢复；
- `tests/ui.test.js`：九个页面可打开且无控制台报错、快速添加与刷新持久化、完成率 67%、手动保存与 Ctrl+S、开发新增/移动/统计、项目筛选与新建、自媒体三张图表、客户删除级联、健身日历、饮食日历与饮水、游戏时长、备份导出与非法导入、清空二次确认、首页摘要与模块统计一致、主题持久化、空状态、存储不可用提示。

## 7. 目录结构

```
myapp/
├── index.html            # 应用外壳（侧边导航 + 顶栏 + 视图容器）
├── server.js             # 零依赖本地静态服务器（可选）
├── css/styles.css        # 设计系统：颜色、间距、卡片、看板、日历、图表
├── js/
│   ├── core.js           # 纯逻辑层：统计、日期、格式化、导入校验（无 DOM）
│   ├── store.js          # 数据层：localStorage 读写、订阅、导出/导入/清空
│   ├── ui.js             # 通用组件：图标、弹窗、表单、Toast、图表、日历
│   ├── sample.js         # 示例数据
│   ├── app.js            # 路由、主题、保存入口
│   └── views/            # 九个模块视图
├── tests/                # core / store / ui 三层测试
├── PRD.md                # 产品需求文档
└── DEVPLAN.md            # 开发计划与阶段记录
```

## 8. 边界（第一版不做）

不做登录注册、不做云数据库与多端同步、不做手机端适配、不做部署上线、不做多人协作与分享。数据只在这台电脑的这个浏览器里，需要迁移时用 JSON 备份。
